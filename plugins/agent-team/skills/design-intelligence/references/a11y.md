# Accessibility

Target WCAG 2.1 AA. Most of it costs nothing if done while building, and is
expensive to retrofit.

## Non-negotiable

**Keyboard**
- Every interactive element reachable by Tab, in a sensible order.
- Visible focus indicator, 3:1 against its surroundings. Never `outline: none`
  without a replacement.
- Escape closes modals and menus; focus returns to the trigger.
- Focus is trapped inside an open modal, and only there.

**Semantics**
- Real `<button>` for actions, real `<a href>` for navigation. A clickable div
  is invisible to assistive tech and unreachable by keyboard.
- One `<h1>` per page; heading levels do not skip.
- Landmarks: `<nav>`, `<main>`, `<header>`, `<footer>`.
- Lists marked up as lists; tables with real `<th>` and scope.

**Forms**
- Every input has a `<label>` associated by `for`/`id`.
- Errors linked with `aria-describedby` and announced via a live region.
- Grouped controls wrapped in `<fieldset>` with a `<legend>`.

**Images and icons**
- Meaningful images have `alt` describing their purpose, not their appearance.
- Decorative images have `alt=""`.
- Icon-only buttons have an accessible name via `aria-label`.

**Colour**
- Contrast: 4.5:1 body, 3:1 large text and UI boundaries.
- Colour is never the only carrier of meaning. Pair it with text, icon, or shape
  - a red border alone does not communicate an error.

**Motion**
- Honour `prefers-reduced-motion`.
- Nothing flashes more than three times per second.

## Quick self-check

1. Unplug the mouse. Complete the main flow with the keyboard only.
2. Zoom to 200%. Does anything overlap or get cut off?
3. Tab through. Can you always see where focus is?
4. Read every error message aloud. Does it say how to fix the problem?
5. Check contrast on muted text specifically - it is the usual failure.

Automated checks (axe, Lighthouse) catch perhaps a third of real issues. They
are a floor, not a pass.
